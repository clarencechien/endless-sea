# 窗景 PoC — Handoff

> 給下一個接手的 agent。請用台灣正體中文與使用者（Clarence）溝通。
> 狀態日期：2026-11-09｜版本：PoC v1（單檔 HTML，已發佈為 claude.ai artifact）

## 1. 這是什麼

靈感來自 Felix Rieseberg 文章中的做法：用 Depth Anything V2 把一張照片轉成約 50 KB 的深度圖，含兩個通道——

- **柔和（soft）通道**：做視差，鏡頭飄移時桅桿、號誌、近處大樓在天際線前滑動。
- **銳利（sharp）通道**：做遮擋，讓火車能消失在建築物後面。

燈光與火車全部由 GPU 疊在照片上，幾乎不吃 CPU。

使用者問了兩個延伸方向，這個 PoC 兩個都做了：

1. **世界之窗**：各國城市依「此刻真實太陽位置」顯示白天／黃昏／夜晚。
2. **車窗**：從火車車窗看出去的景象。

前一輪對話的可行性結論（已跟使用者講過）：
- 世界之窗**可行性高**，正好在「單張照片＋小幅鏡頭飄移」的舒適區。難點是一張照片只有一種光線，需要「發光遮罩」第三通道。
- 車窗**要換用法**：單張照片＋深度圖撐不住持續橫向移動（會露出 disocclusion 破洞）。深度圖改當「自動切層」工具，走經典多層視差捲動；近景（電車線桿）建議程序生成；沉浸感主要來自車窗本身（窗框、倒影、雨滴、隧道）。

## 2. 檔案

```
chuangjing.html   單檔 PoC（HTML + CSS + 內嵌 JS + 兩支 GLSL shader），無外部 JS 依賴
shot.py           Playwright 截圖驗證腳本（swiftshader 跑 WebGL）
HANDOFF.md        本文件
```

已發佈 artifact 標題「窗景 PoC」，icon `window`。若要更新同一個 artifact，請向使用者要 URL（或用 Artifact list 找），先 read 再 publish。

### Artifact 環境限制（改 code 前必讀）
- 頁面會被包上 `<!doctype><head><body>` 骨架，所以檔案**不寫** html/head/body 標籤，`<title>` 與 `<style>` 放檔頭。
- CSP：外部 script 只能從 cdnjs / jsdelivr / unpkg 等白名單載入，字型只能 Google Fonts；**fetch 外部網址會被擋**。這也是為什麼不能在瀏覽器內從 Hugging Face 載模型做即時深度估計。
- 不能 `alert/confirm/prompt`，不能開下載連結，相機等裝置 API 預設被拒。
- 主題 token：bare `:root` 是淺色，兩個 dark block 只重定義 token。canvas 場景本身不跟主題走。

## 3. 架構

### 3.1 世界之窗（`FS_WORLD`）

每個場景 = 三張貼圖：

| 貼圖 | 內容 | 取樣 |
|---|---|---|
| `uPhoto` | 照片（白天中性光） | LINEAR |
| `uDepth` | **R = 柔和深度、G = 銳利深度**（白＝近） | LINEAR |
| `uEmi` | 發光遮罩：0＝非窗戶，1–255＝該窗格的隨機 seed | **NEAREST**（避免 seed 被內插） |

**座標約定**
- `vUv`：螢幕座標，**y 向下**（0 在上），已在 vertex shader 翻好，與 canvas 貼圖一致。
- `base = vUv * uFit.xy + uFit.zw`：cover-fit 後的貼圖座標，含 1.09 倍 zoom 預留飄移邊界。
- 視差：`p = base + uDrift * (soft - 0.35)`，迭代兩次。0.35 是「不動的參考深度」。
- 任何位在深度 `d`、場景座標 `L` 的物件，畫面上出現在 `base = L - uDrift*(d-0.35)`。火車（`uTrainBox.z`）與航空障礙燈（`uLights[i].z`）都照這個公式。
- 遮擋：火車只在 `sharp < 火車深度 - 0.012` 的像素畫出（場景比火車遠才看得到火車）。

**天色**
- `sunPos(date, lat, lon)`：簡化 NOAA 公式，回傳仰角與方位角（北為 0、順時針）。
- `KEYS`：依太陽仰角內插的關鍵影格 `[elev, 天頂色, 地平線色, 建築環境光乘數]`，-18° 到 30°。
- `uNight = clamp((4 - elev)/12, 0, 1)`，控制窗戶亮燈機率、星星、航空燈強度。
- 天空遮罩：`sharp < ~0.03` 視為天空，整片換成漸層＋星星＋太陽。
- 太陽畫面位置：北半球假設面向南、南半球面向北，`sx = 0.5 + 相對方位角/110`，`sy = 0.62 - elev/50*0.55`。
- 窗戶：每格依 seed 有自己的開關週期（7–52 秒），亮燈門檻隨 `uNight` 下降。
- 霧：`pow(1-sharp, 3) * 0.6` 往地平線色混。

**程序場景 `genCity(city)`**
- 同步畫三張 canvas（照片 P、銳利深度 D、發光 E），每個形狀都用同一個 Path2D 填兩次（P 填顏色、D 填深度灰階）。
- 分層由遠到近：山脊 0.07/0.12 → 遠景天際線 0.20–0.28 → 地標 0.37 → 中景 0.42–0.50 → 高架橋 0.57 → 近景大樓 0.70–0.90 → 地面 1.0 → 前景桅桿與電線 0.95–0.97。
- 火車跑在高架橋上方，深度 0.55，所以會被 0.57 的電車線柱和 0.70+ 的近景大樓擋住。
- 柔和通道 `softFrom()`：用多段縮小再放大做模糊（不依賴 `ctx.filter`，Safari 也能跑）。
- `packScene()` 把 soft/sharp 打包成 RG，並量測 800px 寬 WebP 大小顯示在 UI（目前約 11 KB）。
- 七個城市資料在 `CITIES`：經緯度、時區、seed、山的有無、樓高區間、地標種類、調色盤、火車色帶。

### 3.2 車窗（`FS_RAIL`）

| 層 | 來源 | 捲動倍率（`uDist` 係數） |
|---|---|---|
| 遠山 | `genRail().far`，2048×256，週期性正弦山脊（整數頻率保證無縫） | 0.008 |
| 中景房舍 | `genRail().mid`，2048×512，透天厝／鐵皮加蓋／水塔／樹／檳榔樹／廠房，跨邊界的物件畫兩次以無縫 | 0.05 |
| 近景地面 | shader 內 value noise，依車速拉長成條紋 | 0.9 |
| 電車線桿 | shader 程序生成，寬度與透明度隨車速做動態模糊 | 0.35 |
| 電車線 | 掛在線桿之間的下垂曲線，**跟著線桿位置走但看起來幾乎靜止**（真實感關鍵） | — |

- `uDist += kmh/100 * dt`（JS 端累積，換車速不會跳）。
- 隧道：每 140 個 dist 單位中的 120–128 段，`uTunnel` 漸入漸出，畫隧道燈條紋。
- 車廂內燈 `uInterior = clamp(night*1.1 + tunnel, 0, 1)`。
- 玻璃倒影：強度 ≈ 室內亮度 / 窗外亮度，所以夜間與隧道內倒影自動變明顯。倒影內容是鏡像的座椅剪影＋天花板燈帶。
- 下雨：斜向雨痕（角度隨車速從 0.15 到 1.25 rad）＋靜態水珠，並壓暗天色、關掉太陽。
- 遠景／中景貼圖用 **premultiplied alpha** 上傳，合成公式 `col*(1-a) + rgb*amb`。

### 3.3 上傳流程（世界之窗）

`#fApply`：照片縮到最寬 1600px → 深度圖轉灰階、正規化到 0–255（可勾「黑色代表近」反轉）→ 沒給深度圖就用上黑下白漸層代替 → 發光遮罩用**隨機格子**（只放在深度 0.12–0.9 的區域）→ 可選擇放火車（畫面 70% 高、深度 0.5）。天色依目前選的城市。

### 3.4 UI

- 模式切換、拆解檢視（世界：合成／照片／柔和深度／銳利深度／發光遮罩；車窗：合成／遠景層／中景層／發光遮罩），用 `uChannel` 在 shader 內早退輸出。
- 城市 chip 每 250ms 更新各城市當地時間與時段（白天／黃金時刻／藍調時刻／入夜／夜晚）。
- 時間偏移 ±12h、「快轉一天」（每秒 0.5 小時）、鏡頭飄移三種模式（自動／跟著游標／固定，`prefers-reduced-motion` 時預設固定）。

## 4. 驗證方式

```bash
pip install playwright --break-system-packages   # 若環境沒有
python3 shot.py   # 在 chuangjing.html 同目錄執行
```

會輸出 `s_world.png`、`s_world_night.png`、`s_rail_night.png`、`s_rail_day.png`，並印出 console 訊息。shader 編譯失敗時頁面會顯示「著色器編譯失敗」，console 會有 info log。`ERR_TUNNEL_CONNECTION_FAILED` 是 Google Fonts 在沙箱連不到，可忽略。

## 5. 已知問題與限制

1. **場景是程序生成的假照片**：當時沙箱連不到 Hugging Face（`CONNECT tunnel failed 403`），無法跑 Depth Anything V2，也拿不到 GitHub 上的範例照片。真流程目前只能靠使用者上傳。
2. **上傳模式的窗戶遮罩是隨機格子**，不是真窗戶位置，夜景說服力最弱。
3. 鏡頭只能小幅飄移（drift 約 ±0.03），拉大就看到前景邊緣拉扯，這是 2.5D 的本質限制。
4. 程序城市的視覺品質是「示意級」，近景下排小店有點糊；地標都是通用造型，刻意不做精確複製。
5. 車窗的太陽位置沿用世界之窗的方位角對應，沒有考慮列車行進方向。
6. 頁面在 claude.ai artifact 環境運作；若搬到 ai-apps.work 自有網域，CSP 限制會不同，可改成在瀏覽器內跑模型。

## 6. 建議的下一步（依優先順序）

1. **接上真照片與真深度圖**：在能連 Hugging Face 的環境（使用者本機或 Claude Code）用 `depth-anything/Depth-Anything-V2-Small-hf` 對一張台北天際線照片離線產生深度圖，替換程序場景，確認說服力。
   - ⚠️ 授權：**只有 Small 是 Apache-2.0**，Base／Large 是 CC-BY-NC-4.0（不可商用）。若未來要上 ai-apps.work 變現，用 Small。照片素材（尤其網路攝影機截圖）也要確認授權。
2. **真窗戶遮罩**：三選一評估
   - (a) 同視角白天＋夜景兩張照片，夜景減去壓暗的白天＝發光遮罩；
   - (b) 用影像模型從白天圖生成夜景版再相減（風險：建築位移對不齊）；
   - (c) 用分割模型抓 window／building 類別再切格。
3. **離線打包工具**：一支腳本吃「照片 → 輸出 photo.webp + depth.webp（RG）+ emissive.png」，讓加城市變成資料工作而非寫程式。
4. **車窗換真全景**：依深度門檻切成 2–3 層 → inpaint 補洞 → outpaint 做無縫循環。近景線桿維持程序生成。
5. 若要多城市同畫面（世界之窗牆）：單一 canvas + 貼圖 atlas，不要每城市一個 WebGL context（瀏覽器有數量上限）。
